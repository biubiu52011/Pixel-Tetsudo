# Date: 2026-08-31

## Summary

Removed dead UI elements, simplified information density, and repositioned tourism content. All 4-language display identity fixes from 4.1.1 preserved. Canonical data unchanged.

---

## Changes Made

### BATCH A: REMOVE (Dead / Redundant UI)

#### A1: Sort Mode Buttons — REMOVED
**File:** js/search-ui.js
**Lines removed:** ~15 (HTML generation) + ~10 (event handler)
**Reason:** RouteEvaluator is never defined. BFS returns single route. Buttons were dead UI.

#### A2: Direction Arrows (↑↓) — REMOVED  
**File:** js/search-ui.js
**Lines removed:** ~5
**Reason:** Station order already implies direction. Zero information added.

#### A3: Branch Indicator (↳) — REMOVED
**File:** js/data-state.js
**Lines removed:** ~5
**Reason:** Internal data structure exposed to users. Passengers don't need branch hierarchy.

#### A4: Train Count Badge — REMOVED
**File:** js/data-state.js
**Lines removed:** ~8
**Reason:** Unlabeled raw number. meaningless without context.

### BATCH B: SIMPLIFY

#### B1: Segment Count — REMOVED
**File:** js/search-ui.js
**Change:** Removed "X segments" span from result header
**Reason:** Redundant with station timeline visualization

#### B2: Realtime Modal — COLLAPSED by default
**File:** js/realtime-view.js
**Change:** When status is "normal" or "no_data", interval/cause/updated sections are hidden (display:none)
**Reason:** Most users just want to know "is my line on time?"

#### B3: Operator Filter — COLLAPSIBLE
**File:** js/realtime-view.js + css/style.css
**Change:** Filter bar starts collapsed. "Show all operators" toggle button appears. Click to expand.
**Reason:** 21 operator buttons overwhelming on first view. Most users filter to 1-3 operators.

### BATCH C: MOVE

#### C1: Nearby Spots — MOVED outside route card
**File:** js/search-ui.js
**Change:** Spots section no longer injected inside .search-result. Now appended after using insertAdjacentHTML.
**Reason:** Transit and tourism are different intents. Should not compete in same card.
