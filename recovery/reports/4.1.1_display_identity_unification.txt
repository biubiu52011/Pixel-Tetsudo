# 4.1.1 — Display Identity Unification
# Date: 2026-08-31
# Rule: CODE CHANGE - Fix systemic raw ID leaks

---

## Summary

Established a unified display identity resolution layer and fixed 4 P0 issues where raw internal IDs were leaking into user-facing UI across Route Search, History, Trains Detail, and Realtime pages.

---

## Changes Made

### 1. Foundation: RailwayDB.resolveLineName() added to db-loader.js

Added a new method to the canonical data access layer:

```js
resolveLineName: function(id, lang) {
  if (!id) return '';
  lang = (lang || window.currentLang || 'ja').toLowerCase();
  var line = data.lines ? data.lines[id] : null;
  if (!line) return id;
  var nameKey = 'name' + lang.charAt(0).toUpperCase() + lang.slice(1);
  return line[nameKey] || line.nameJa || line.nameEn || line.name || id;
}
```

This follows the same pattern as the existing `resolveStationName()` method.

### 2. js/search-ui.js (Line ~255) — Route Search line names

Before: `var lineName = seg.lineName || (seg.lines && seg.lines[0]) || '';`
After: `var lineName = lineId ? RailwayDB.resolveLineName(lineId, currentLang) : null;`

Fixes: Raw IDs like `ChuoRapid`, `KeihinTohoku` now show `中央線快速`, `京浜東北線` in JA mode.

### 3. js/history.js (Line ~104) — History line list

Before: `[...new Set(entry.lineInfo.flat())].join(", ")` — raw IDs
After: Same but mapped through `RailwayDB.resolveLineName(lid, _lang)`

Fixes: History entries now show readable line names instead of `ChuoRapid, Sobu`.

### 4. js/trains-page.js (Line ~242) — Detail title

Before: `fusedLine.nameJa || fusedLine.nameEn || fusedLine.name` (JA-first, always Japanese)
After: Language-aware resolution via `_tKey = 'name' + langCapitalized`

Fixes: EN user now sees "Chuo Rapid Line" instead of "中央線快速" in the detail title.

Also fixed: SVG station labels in trains-page.js now use `resolveStationName()` consistently.

### 5. js/realtime-view.js (Line ~136) — Operator filter buttons

Before: `escapeHtml(op)` — raw operator ID
After: `escapeHtml(tOp(op))` — translated operator name

Also fixed: `getDisplayName()` now uses the same language-aware pattern as data-state.js
(before: hardcoded `nameJa` first; after: language-key-first with fallback)
