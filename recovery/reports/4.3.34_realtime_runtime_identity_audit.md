## 3. Dead Code Analysis: mapLineCodeToLineId

### 3.1 Function Definition (data-fusion.js:40-50)

function mapLineCodeToLineId(lineCode, tripId) {
  if (!lineCode) return null;
  var knownLines = window.DataLayer.getAllLines() || window.UNIFIED_LINES || {};
  var ids = Object.keys(knownLines);
  for (var i = 0; i < ids.length; i++) {
    if (knownLines[ids[i]].operator === lineCode) return ids[i];  // BUG: compares operator, not code
  }
  return null;
}

### 3.2 Issues Identified

1. LOGIC ERROR: Compares operator === lineCode, not code === lineCode. If ODPT returned JR-East as a lineCode, this would match the FIRST JR-East line (e.g., Agatsuma), not the intended line.

2. NEVER CALLED: Zero callers anywhere in the codebase. Dead code.

3. UNUSED ODPT FIELDS: odptData.trains and odptData.realtimePositions are always empty because loadTrainPositions() is a stub: async function loadTrainPositions() { try { return; } catch(e) {} }

### 3.3 Impact Assessment

| Issue | Runtime Impact | Risk |
|-------|---------------|------|
| mapLineCodeToLineId logic error | NONE (never called) | N/A |
| loadTrainPositions stub | No position data shown | Acceptable (deferred feature) |
| odptData.trains empty | No raw train data | Acceptable |
| odptData.realtimePositions empty | No position indicators | Acceptable |

All issues are in dead/unreachable code. No impact on current functionality.

## 7. Key Findings

1. Runtime Identity Chain Is Healthy
   The active data flow (ODPT -> DataFusion -> DataState -> UI) correctly preserves canonical line identity at every stage. No mismatches, no lost data, no identity corruption.

2. Dead Code: mapLineCodeToLineId
   A buggy function at data-fusion.js:40 designed for line-code-based ODPT mapping was never integrated. It compares operator === lineCode instead of code === lineCode. Since it has zero callers, it poses no risk.

3. Position Tracking Not Implemented
   loadTrainPositions() is a stub. odptData.trains and odptData.realtimePositions are always empty. This is a feature gap, not a bug — position tracking was planned but deferred.

4. 52 Lines Lack Code Field
   Nearly a third of canonical lines (52/156) have no code field. Acceptable because current ODPT integration uses operator-level queries.

## 8. Architecture Assessment

### Planned Architecture (Not Implemented)

The planned architecture has a bug in mapLineCodeToLineId and is not yet active. When implemented, it should:
1. Fix mapLineCodeToLineId to compare code === lineCode instead of operator === lineCode
2. Implement loadTrainPositions() to actually fetch and parse position data
3. Add position markers to the UI
