## Systemic Root Causes

### Root Cause 1: No Unified Display Name Resolution

There are 5 independent implementations of display name resolution scattered across the codebase:

| File | Function | Pattern |
|---|---|---|
| data-state.js:72-74 | inline | lang -> nameKey -> nameJa -> nameEn -> name -> id |
| realtime-view.js:13-18 | getDisplayName() | Same as above |
| trains-detail.js:13-18 | getDisplayLineName() | Same as above |
| trains-page.js:242 | inline | nameJa -> nameEn -> name (JA-first, WRONG) |
| search-ui.js:255 | inline | seg.lineName (RAW ID, WRONG) |
| history.js:104 | inline | lineInfo.flat() (RAW ID, WRONG) |

**Impact:** 3 pages show raw IDs or wrong-language names. The other 3 are correct but duplicate code.

**Fix:** Create window.DisplayResolver.getLineName(line, lang) as a single shared function. Replace all 5 implementations.

---

### Root Cause 2: lineInfo Stores Raw IDs, Not Display Names

The route search pipeline stores line.name (English snake_case) in lineInfo. Any UI that reads lineInfo for display purposes will show raw IDs.

**Affected pages:**
- Route Search result segments (search-ui.js:255)
- History line list (history.js:104)

**Fix options:**
(a) Store display names in lineInfo at build time (requires passing lang to buildRouteSegments)
(b) Resolve display names at render time (cheaper, but needs lang context)

**Recommendation:** (b) - resolve at render time using RailwayDB.getLine(lineId) + currentLang.

---

### Root Cause 3: Tourism Data Is Monolingual

The tourism data in railway_data.json only has English 
ame fields. No 
ame_ja, 
ame_zh, 
ame_ko variants exist.

**Impact:** All 4 languages fall back to English for spot names. The code in tourism-detail.js has the resolution logic ready, but the data doesn't support it.

**Fix:** Add multilingual spot names to tourism data. This is a DATA task, not a code task.

## Product Design Direction

### Core Principle

> **Every piece of information on screen must answer a question the user actually has.**

### Information Hierarchy for Line Cards

`
Level 1 (primary): OS code badge + Line display name
Level 2 (secondary): Interval (from -> to) or status
Level 3 (tertiary): Branch indicator, train count badge
`

NOT:
`
Level 1: Line name (Japanese)
Level 2: Line name (English)     <- DUPLICATE
Level 3: Line name (internal ID) <- LEAK
`

### Information Hierarchy for Route Search Results

`
Top: Total duration + transfers
Middle: Station sequence (visual timeline)
Below: Segment breakdown (line name + interval + duration)
Bottom: Realtime status badge (if available)
`

### Information Hierarchy for History Entries

`
Primary: From station -> To station
Secondary: Duration + lines (display names, not IDs)
Tertiary: Timestamp
`
