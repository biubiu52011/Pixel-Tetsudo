### P1 — Architecture Drift / Display Identity Inconsistency

**ISSUE-01: `window.tLineName` is an ORPHAN REFERENCE**
- Location: `js/data-state.js:72`
- Code: `(window.tLineName && window.tLineName(line)) || line.nameEn || line.name || lineId`
- Problem: `window.tLineName` is NEVER defined anywhere in the codebase. The first resolver in the chain is dead code.
- Impact: `data-state.js` renderCard always falls through to `line.nameEn || line.name || lineId`, which is language-agnostic and may show English names in JA mode.
- Classification: LEGACY_PATH (residual from before 4.1.1)

**ISSUE-02: Hardcoded operator ID in data-state.js renderCard**
- Location: `js/data-state.js:78`
- Code: `else if (line.operator === "JR-East")`
- Problem: Direct comparison to raw operator ID `"JR-East"`. Should use `tOp(line.operator)` or at minimum `tOp("JR-East")` for consistency.
- Impact: Minor — this is a fallback image path, not user-facing text, but it sets a bad precedent.
- Classification: TECHNICAL_LEAK (low severity)

**ISSUE-03: Multiple display name resolution patterns coexist**
| File | Pattern | Correct? |
|------|---------|----------|
| search-ui.js:244 | RailwayDB.resolveLineName(lineId, lang) | ✅ CORRECT |
| history.js:104 | RailwayDB.resolveLineName(lid, lang) | ✅ CORRECT |
| trains-detail.js:16 | line[_nameKey] \|\| nameJa \|\| nameEn \|\| name \|\| id | ✅ CORRECT |
| trains-page.js:242 | fusedLine[_tKey] \|\| nameJa \|\| nameEn \|\| name \|\| id | ✅ CORRECT |
| realtime-view.js:15 | Same as trains-detail | ✅ CORRECT |
| data-state.js:72 | tLineName(line) \|\| nameEn \|\| name \|\| lineId | ❌ BROKEN (tLineName undefined) |
- Root cause: 4.1.1 added `RailwayDB.resolveLineName()` but `data-state.js` renderCard was not migrated.
- Classification: LEGACY_PATH (migration gap from 4.1.1)

### P2 — Cross-Page Consistency Risks

**ISSUE-04: `window.tLine` circular self-reference in data-state.js**
- Location: `js/data-state.js:49-50`
- Code: `function tLine(code) { return (window.tLine && window.tLine(code)) || code || ""; }`
- Problem: This local function references `window.tLine` which is never set by data-state.js itself. It creates a circular check that always resolves to the fallback `code`.
- Note: `realtime-view.js:9` has its OWN local `tLine` arrow function that delegates to `window.tLine`. These are independent implementations.
- Classification: LEGACY_CODE (dead pattern, no functional impact but confusing)

**ISSUE-05: `data/铁道/` stale backup directory**
- Contains 14 JS files + 1 CSS, all dated 2026/8/30
- NOT referenced by any HTML page (verified via rg)
- Diverged from `js/`: missing data-fusion.js, data-layer.js, data-state.js, lang-init.js, line-presentation-service.js, local-railway-data.js, security.js, tab-switch.js, tourism-detail.js, tourism-proximity.js
- Contains unique files not in js/: line-operation-systems.js (but data/core/ has newer version), train-timetable.js
- Classification: LEGACY_CODE (orphaned backup, zero runtime impact)
