# 4.0.3 — Realtime Page: First-Time User IA Audit
# Date: 2026-08-31
# Rule: AUDIT ONLY — NO CODE CHANGES

---

## Executive Summary

The Realtime page is architecturally sound: it shares the same `DataState.renderList()` / `DataState.renderCard()` rendering pipeline as Trains, ensuring visual and functional consistency. The modal detail view correctly resolves display names. However, there is **one critical IA flaw**: the operator filter bar buttons display raw operator IDs instead of translated names. This is the same class of problem as F-01 in Route Search, but in a different module.

---

## F-R01 🔴 CRITICAL — Operator Filter Buttons Show Raw IDs

**Location:** `js/realtime-view.js:136`
```js
html += '<button class="rs-filter-btn' + (_selectedOperator === op ? ' active' : '') + '" data-operator="' + escapeHtml(op) + '">' + escapeHtml(op) + "</button>";
```

**Problem:** The filter button text uses `escapeHtml(op)` — the raw operator ID from `railway_data.json` (e.g., `JR-East`, `TokyoMetro`, `Seibu`, `Odakyu`). The `tOp()` function IS defined in the same file (line 10) and IS used correctly in `data-state.js:237` for operator group titles, but was **omitted** from the filter bar.

**What the user sees (JA mode):**
```
[All] [JR-East] [TokyoMetro] [Seibu] [Odakyu] ...
```

**What it should show:**
```
[すべて] [JR東日本] [東京メトロ] [西武] [小田急] ...
```

**User impact:** High. The filter bar is the first interactive element a user sees. Raw IDs like "JR-East" and "TokyoMetro" are not user-facing labels — they are internal database keys. A Japanese user would not recognize "TokyoMetro" as 東京メトロ.

**Root cause:** The developer defined `tOp` at line 10 but forgot to apply it in the filter bar rendering. The same pattern was fixed in `data-state.js:237` (operator group titles) but missed in `realtime-view.js:136` (filter buttons).

**If fixed:** Minimal one-word change — `escapeHtml(op)` → `escapeHtml(tOp(op))`.

**Category:** TECHNICAL-LEAK

## F-R05 🟡 QUESTIONABLE — status.unknown Used for "Last Updated Time" Fallback

**Location:** `js/realtime-view.js:100-102`
```js
} else if (status === "no_data") {
  updateTime = t("status.no_data");
} else {
  updateTime = t("status.unknown");
}
```

**Analysis:** When no ODPT data is available and the status is not explicitly "no_data", the "Last Updated" field shows `status.unknown` ("不明" in JA). This is semantically odd — "不明" (unknown) as a timestamp label is confusing. It should probably say something like "数据不可用" (data unavailable) or simply be blank.

**User impact:** Low. This only appears in the modal's "Last Updated" section when ODPT data is absent. Most users will never see it since ODPT data loads for most operators.

**If deleted:** The field would show empty or a different message. No functional loss.

**Recommendation:** Replace `t("status.unknown")` with `t("status.no_data")` or an empty string in this context. The `status.unknown` key is better reserved for actual unknown status states, not missing metadata.

**Category:** QUESTIONABLE

## F-R08 🔵 INTENTIONAL — Operator Filter Only on Realtime (Not Trains)

**Observation:** Realtime has an operator filter bar. Trains does not.

**Analysis:** This is a deliberate design choice. The Realtime page's primary task is "which lines are having issues right now?" — filtering by operator helps users quickly focus on their通勤 operator. The Trains page's primary task is "show me all lines and their details" — a filter would add complexity without proportional benefit since the OS-based grouping already provides operator-level organization.

**Industry comparison:** Yahoo!乗換案内 shows operator filters on its "delay info" page but not on its "line guide" page. This matches the pattern.

**Category:** INTENTIONAL

## F-R10 🟡 QUESTIONABLE — Status Icon Uses Unicode Symbols (Accessibility)

**Location:** `js/data-state.js:12-17`
```js
normal:    { icon: "○", cls: "rs-status-icon-normal",    label: "normal"    },
delayed:   { icon: "△", cls: "rs-status-icon-delayed",  label: "delayed"   },
suspended: { icon: "×", cls: "rs-status-icon-suspended", label: "suspended" },
no_data:   { icon: "◌", cls: "rs-status-icon-no-data",   label: "no_data"  },
no_odpt:   { icon: "●", cls: "rs-status-icon-no-odpt",   label: "no_odpt"  }
```

**Analysis:** The status icons use Unicode geometric shapes (○ △ × ◌ ●). These are visually intuitive (circle = good, triangle = warning, X = stop) but may not render consistently across all browsers/OSes. More importantly, they have no accessible text alternative — screen readers would announce the raw Unicode character or nothing at all.

**User impact:** Low for sighted users. Medium for accessibility.

**If changed:** Would need ARIA labels or text equivalents added.

**Recommendation:** Acceptable for current pixel-art aesthetic. Add `aria-label` attributes in a future polish pass if accessibility becomes a priority.

**Category:** QUESTIONABLE

## F-R11 🟢 GOOD — DataFusion Subscribe Pattern Is Robust

**Location:** `js/realtime-view.js:186-196`
```js
if (window.DataFusion) {
  window.DataFusion.subscribe(function(fusedData) {
    if (fusedData && fusedData.lines && Object.keys(fusedData.lines).length > 0) {
      render();
      if (_selectedOperator) {
        renderFiltered();
        renderFilterBar(_latestLines);
      }
    }
  });
}
```

**Why it works:** When ODPT data arrives (or updates), the page re-renders automatically. The operator filter state is preserved across re-renders. This is a clean reactive pattern.

**Category:** GOOD

## F-R12 🟢 GOOD — Polling Fallback for Async Data Loading

**Location:** `js/realtime-view.js:199-211`
```js
var _pollCount = 0;
var _pollTimer = setInterval(function() {
  _pollCount++;
  var fused = getLines();
  if (fused && fused.lines && Object.keys(fused.lines).length > 0) {
    clearInterval(_pollTimer);
    render();
  } else if (_pollCount > 20) {
    clearInterval(_pollTimer);
    if (!container.querySelector(".rs-line-card")) {
      container.innerHTML = '<div class="rs-empty">' + t("status.load_error") + '</div>';
    }
  }
}, 300);
```

**Why it works:** Handles the case where DataFusion hasn't loaded yet (async script loading). Shows loading spinner during poll, error state if data never arrives after 6 seconds.

**Category:** GOOD
