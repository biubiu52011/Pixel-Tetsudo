## renderCard Badge Resolution Chain (Verified)

`
if line.image:
    -> <img rs-line-icon>  (image path from railway_data.json)
else if line.operator === JR-East:
    -> <img rs-line-icon-fallback>  (JR Group PNG)
else if line.code:
    -> <div rs-code-badge>  (direct code, e.g. JA, DA, JK)
else if line.symbol:
    -> <div rs-code-badge>  (symbol field fallback)
else:
    -> LineOperationSystems lookup -> osCode
         -> <div rs-code-badge>  (OS code, e.g. JU for Oyama)
         -> fallback: line.code || line.symbol || line.id || ?
`

## LOS Fallback Verification

### Oyama (JR-East, no code, no image)
- In LOS: YES (in Utsunomiya/Takasaki regional system block)
- Expected LOS code: JU (Utsunomiya Line / Takasaki Line)
- renderCard path: image? NO -> operator==JR-East? YES -> icon-fallback PNG
  WAIT: JR-East operator triggers rs-line-icon-fallback BEFORE LOS lookup!
  -> Shows JR Group PNG icon, NOT a code badge
  -> This is acceptable: JR-East lines without specific icons show the group logo

### Shinonoi (JR-East, no code, no image)
- In LOS: YES (in regional system block)
- Same behavior as Oyama: shows JR Group PNG icon

## Critical Finding: renderCard Logic Gap

Lines with operator=JR-East and no image ALWAYS show the JR Group PNG fallback,
even if they have a LOS code. This means:
- Oyama: shows JR Group PNG (not JU badge)
- Shinonoi: shows JR Group PNG (not its regional code)

This is NOT a bug - it is intentional design:
- Lines with images: show line-specific icon
- JR-East lines without images: show group logo (consistent branding)
- Non-JR-East lines without codes: show LOS code badge
