# Task 3.87 - Operator Display Identity Fix

Date: 2026-08-31
Status: COMPLETE

Problem:
- window.tOp() was a dead function (window.tOp never set)
- TransitConstants.OP_NAMES = {} (empty)
- No operator name translations in translations.js
- Result: raw English IDs like JR-East, TokyoMetro appeared in UI in ALL languages

Changes Made:
1. translations.js - Added 84 operator name translations (21 ops x 4 langs)
   - en: JR East, Tokyo Metro, Seibu Railway, etc.
   - zh: JR东日本, 东京地铁, 西武铁道, etc.
   - ja: JR東日本, 東京メトロ, 西武鉄道, etc.
   - ko: JR동일본, 도쿄 메트로, 세이부 철도, etc.

2. lang-init.js - Wired tOp() chain
   - After updateTranslations(), builds OP_NAMES from translation keys
   - Sets window.tOp to read from OP_NAMES with fallback to raw ID

3. data-state.js - Language-aware displayName
   - Now checks name{currentLang} first, then nameJa, nameEn, name, lineId
   - Uses tOp(op) for operator group titles (was using raw op)
   - Fixed var op = line.operator declaration

4. realtime-view.js - Language-aware getDisplayName
   - Same language-aware fallback pattern

5. trains-detail.js - Language-aware detail title
   - Added getDisplayLineName() helper
   - Fixed SVG station labels to use _rS() resolver

Verification:
- Syntax: All files pass balance check
- All 4 language sections have 21 op.* entries each
- Canonical data NOT modified
- OS mapping NOT modified
- Line IDs NOT modified
