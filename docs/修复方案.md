## 二、修复方案

### 阶段 1：安全修复（S1-S2）— 立即执行

**S1 密钥处理**
- 方案 A（推荐）：两个 key 从代码移除，改为 `localStorage` 用户配置（设置页提示用户自行填入 ODPT key），代码读取 `localStorage.getItem('odpt_challenge_key')`，缺失时提示"请配置 API Key"
- 方案 B：保持现状但接受风险（challenge key 本就是公开设计），仅提醒用户可注册新号重置
- ⚠️ 注意：密钥已进 git 历史，无法通过简单 commit 删除；如需彻底清除需 `git filter-repo` 重写历史（会破坏现有提交链，建议谨慎）

**S2 sightseeing.js 转义**
- 为 `name/desc/exitText/distText` 加 `window.escapeHtml()` 包裹（common.js 已有全局定义）
- 同步检查 `data-state.js`/`realtime-view.js` 的 ODPT 字段渲染点补转义

### 阶段 2：数据修正（D1-D5）— 需 Wiki 校对

**D1-D2 错误车站列表**
- 从 Wikipedia/官方路线图核对桐生线（太田-桐生 14 站）、佐野线（館林-葛生 10 站）、山形线（福島-新庄）真实车站
- railway_data.json 锁定 → 在 `db-loader.js` `applyDataCorrections()` 修正层覆盖 stations

**D3 英文站名**
- 方案：生成 2506 站的英文站名（可用 `data.name_map` 已有英文映射回填，或补充 Wikipedia 罗马字）
- 写入 `station_i18n.json` 或修正层 `STATION_NAME_MAP`

**D4 北绫濑支线**
- 在修正层新增 `ChiyodaBranch`（branchOf='Chiyoda'，站：北綾瀬，交汇点 Ayase），并从千代田主线 stations 移除北綾瀬

**D5 图标/ODPT key 对齐**
- 幽灵 key 分类处理：
  - 真别名（SeibuIkebukuro↔Ikebukuro、TobuTojo↔Tojo 等）→ 保留映射，加注释
  - 真幽灵（MIR/TWR/ShonanMonorail/NipporiToneri/KitaAyase）→ 修正为线路数据实际 key
- ODPT LINE_TO_OPERATOR 11 个幽灵（Isesaki/Nikko/Orange/Rinko 等）→ 映射到实际线路 ID
